- **Backdrop effects draw on a WebGL 2 canvas.** `El::backdrop_lens` (`Lens::prism()` included, frosted or clear) and `El::backdrop_blur` drew only their element's fill there, because wgpu offers a WebGL 2 canvas only as a render target, and the renderer can't copy from one. Now a frame with a backdrop effect draws into a texture the renderer keeps, and one more pass puts that texture on the canvas; a frame with none draws straight into the canvas as before. `Cx::backdrop_copies()` is now true on a WebGL 2 canvas, so a view that thins its fill on it (`rune_kit::glass_draws`) does there too. On a page with a compositor it stays false and the effects still draw their fill, because a compositor's frames don't take this path. WebGPU canvases and native windows are unchanged. A page that starts on the CPU (the default) now hands over to a WebGL 2 GPU too: before, it waited for wgpu's GL backend to report its first frame done without polling it, so it stayed on the CPU for good. It does not hand over to a software WebGL 2 (SwiftShader, llvmpipe), where a frame takes seconds instead of the CPU painter's milliseconds; there the effects draw their fill, and `globalThis.RUNE_CPU_FIRST = "off"` starts the page on that GPU instead.
