- **Backdrop effects draw on a WebGL 2 canvas.** `El::backdrop_lens` (`Lens::prism()` included, frosted or clear) and `El::backdrop_blur` drew only their element's fill there, because wgpu offers a WebGL 2 canvas only as a render target, which the renderer can't copy what is under an effect from. A frame with a backdrop effect now draws into a texture the renderer keeps, which can be copied, and one more pass puts it on the canvas; a frame with none draws straight into the canvas as before. `Cx::backdrop_copies()` is now true on a WebGL 2 canvas, so a view that thins its fill on it (`rune_kit::glass_draws`) does there too. A frame a compositor draws on a WebGL 2 canvas still draws its effects' fill. WebGPU canvases and native windows are unchanged. A page that starts on the CPU (the default) now also hands over to a WebGL 2 GPU: wgpu's GL backend answers "work done" only when the device is polled, and the hand-over waited for that answer without polling, so such a page stayed on the CPU for good. On a slow software GPU (SwiftShader) the first frame with glass can still miss the hand-over's 5 s limit; the page then stays on the CPU and draws the fill.
