- **`Block::Heading(u8)`, a heading line at level 1 to 6, and `on_input_change` on format-only edits.** A heading draws bold and larger (1.6, 1.3 and 1.1 times the field's size for levels 1 to 3), and a span from `.decorations()` overrides that look. Return at the end of a heading starts a paragraph, at its start leaves an empty paragraph above it, and inside one keeps both halves headings. Backspace at its start makes it a paragraph. An empty heading line still draws at body size and line height until it holds text. `Block::same_kind` matches a heading only at the same level, so `toggle_block(Block::Heading(2))` on an H1 makes it an H2. `TextEdit::from_html` reads `<h1>`…`<h6>` outside lists and quotes as headings with no `Mark::Bold`, and `to_html` writes them back. A field whose `allow_blocks` leaves out headings gets a heading, pasted or set, as a paragraph with `Mark::Bold`; heading levels don't matter there, as list levels don't. `Block` is not `non_exhaustive`: an exhaustive `match` on it in an app must add a `Block::Heading(_)` arm. `El::on_input_change` now also runs when a key changes a field's marks or blocks with no text change (⌘B, ⌘I or ⌘U, Tab or Shift+Tab indent, Backspace at the start of a list item, heading, quote or code line, Return on an empty list item, quote or code line, undo or redo of these), so an app that saves from it no longer misses a formatting-only change; a caret or selection move still doesn't call it, also after the app wrote `text` itself. An app's own `toggle_mark`, `toggle_block` or `set_block` call (a toolbar button, an `on_input_key` shortcut) doesn't call it; the app saves that change itself.
